# 全平台帧率与时间步设计（推荐方案）

----------------------------------------

## 背景与现状

- 现有实现为"可变步长 + 平滑时间"模型：
  - 每帧用高精度计时器计算 `dt` 并分发到各模块（参考 src/engine/Application.cpp 主循环）。
  - 支持时间倍率控制（通过 Application 配置）。
  - 计算"平滑 dt"用于展示与诊断（参考 src/core/FrameTimer.hpp）。
- 引擎层未强制固定帧率；VSync/帧交换由 bgfx 后端控制。

该模型简单、低延迟，但在多人确定性、重物理稳定性与低功耗等场景下需要补强。

----------------------------------------

- 采用“固定逻辑步 + 可变渲染步”的混合架构：
  - 引擎主循环仍使用可变 `dt`，保持低延迟与高帧上限。
  - 物理/游戏规则等对稳定性/确定性敏感的模块使用固定逻辑步（例如 60Hz）通过 accumulator 驱动；渲染对状态进行插值。
- 提供可选限帧（Frame Cap）与 VSync 策略开关以适配移动端省电/录制/散热控制等需求。
----------------------------------------

## 引擎层基线（与现状对齐）

- 保留可变 `dt` 的统一分发：src/engine/Application.cpp 主循环。
- 保留/完善时间倍率与单步调试：通过 Application 配置系统。
- 扩展（可选）：在主循环外层增加"目标帧间隔"限帧开关，用于移动端与台式机省电：
  - 参数：`frame_cap_hz = {Off, 30, 60, 90, 120, ...}`。
  - 策略：若一帧执行过快，`os::sleep(remaining_ms)`，优先使用 VSync 保证帧间隔，再以 sleep 微调。

----------------------------------------

- 适用：物理、角色控制、投射体、AI 决策等对数值稳定敏感的系统。
- 模式：固定 `fixed_dt = 1 / tick_rate`（典型为 60Hz）；每帧将可变 `dt` 累加，循环消耗固定步；限制最大子步次数避免“死亡螺旋”。

伪代码（模块内部）：

```
accumulator += clamp(dt, dt_min, dt_max)
steps = 0
while accumulator >= fixed_dt and steps < max_substeps:
    simulate(fixed_dt)
    accumulator -= fixed_dt
    steps += 1
alpha = accumulator / fixed_dt  # 用于渲染插值
```

建议：
- `dt_min, dt_max` 典型取 `[1/120, 1/20]`。
- `max_substeps` 典型取 3~6；超过上限可：
  - 方案 A：丢弃多余累积（会有时间漂移但避免卡死）。
  - 方案 B：在本帧提升 `fixed_dt`（会影响稳定性，不推荐）。
- 插值：对位置/朝向等可插值的状态渲染时按 `alpha` 混合；对“事件型/离散型”状态不要插值（如开火、命中）。

----------------------------------------

## 多人与回放的确定性

- 锁步/回滚框架：
  - 逻辑固定步（同上）；输入统一按帧戳打包；
  - 浮点一致性：尽量减少跨平台的浮点差异（禁用非确定的 SIMD 路径、控制 FPU 舍入、避免依赖未定义行为）。
  - 随机性：统一播种/可重放 PRNG；随机只在逻辑步内消费。
- 录制/回放：
  - 记录输入流 + 版本/种子；
  - 严格禁止在确定性模式下使用“可变 `dt`”的逻辑路径。

----------------------------------------

## 渲染与帧同步

- 渲染步使用可变 `dt`，优先追求低延迟与更高刷新；
- 与逻辑解耦：渲染读取上一固定步与当前 accumulator 的插值状态；
- VSync 策略可暴露为配置项：`vsync = {off, on, adaptive}`，平台后端决定最终呈现节奏。

----------------------------------------

## VR/AR 场景

- 目标高刷新（90/120Hz）；尽可能避免 CPU 侧 frame cap 造成丢帧；
- 若逻辑步跟不上渲染步，优先保证渲染流畅（ASW/重投影由平台支撑）；
- 插值/外推对头部姿态与手柄姿态要谨慎（优先外设层预测，减少渲染侧插值滞后）。

----------------------------------------

## 移动端与省电

- 提供全局帧率上限（Frame Cap）与 VSync 开关；
- 启动自适应负载策略：分辨率缩放（DLSS/FSR/动态分辨率）、后处理质量阶梯；
- 前后台/锁屏/降频场景下自动拉高 `fixed_dt` 上限或降低 tick_rate。

----------------------------------------

## 可配置参数建议

- `tick_rate`：逻辑步频率（默认 60，可选 30/120）。
- `max_logic_substeps`：每帧最大子步（默认 4）。
- `dt_clamp_min/max`：可变 `dt` 钳制范围（默认 [1/120, 1/20]）。
- `frame_cap_hz`：渲染限帧（默认 Off）。
- `vsync`：{off, on, adaptive}。
- `time_scale`：时间倍率（默认 1.0）。
- `deterministic_mode`：是否启用确定性运行约束（默认 Off）。

----------------------------------------

## 与现有代码的落地点

- 继续保留：
  - 可变 `dt` 计算与分发：src/engine/Application.cpp 主循环。
  - 单步与时间倍率：通过 Application 配置系统。
  - 平滑时间增量（仅展示）：src/core/FrameTimer.hpp。
- 新增/扩展：
  - 在各“需要稳定性的模块”内部引入 accumulator 固定步（物理、投射体、AI 等）。
  - 在主循环外层新增可选 `frame_cap_hz`（睡眠到目标帧间隔，配合 VSync）。
  - 暴露上述参数到配置系统/控制台。
  - 为“确定性模式”预留钩子：
    - 禁用所有依赖可变 `dt` 的逻辑路径；
    - 固定随机种子与 PRNG；
    - 记录/回放输入流。

----------------------------------------

## 风险与测试清单

- 长帧容灾：验证 `max_logic_substeps` 与 `dt_clamp` 在极端负载下不发生“死亡螺旋”。
- 插值正确性：对可插值与不可插值的状态分别验证（传送/瞬移时应禁用插值）。
- 多人一致性：跨平台/不同 CPU/GPU 组合下跑确定性回归（比对校验和）。
- 省电/发热：移动设备在不同 `frame_cap_hz` 下的可用性测试。
- VR：在高刷新下无额外限帧，检验姿态延迟与抖动。

----------------------------------------

## 采用建议

- 通用 3D 项目：推荐采纳本方案（固定逻辑步 + 可变渲染 + 可选限帧），以最小代价覆盖大多数玩法与平台。
- 对战/回放/重物理：在上方案基础上开启“确定性模式”，并引入锁步/回滚机制。
- 轻量/休闲/原型期：可临时只用可变步 + 基本钳制；后续再迁移到固定逻辑步。

以上方案不改变现有引擎的低延迟优势，同时为稳定性与跨平台一致性提供可插拔的增强路径。

# ADR 0052：按需增长、热路径复用与预算化内存

- 状态：Accepted / 实现分阶段进行
- 日期：2026-09-07
- 决策依据：maintainer 明确要求取消一刀切固定容量政策，允许无兼容层的架构迁移。

## 背景

固定容量 slot/PMR buffer 有助于预分配和稳定句柄，但泛化成全引擎规则会让正常增长变成 CapacityExceeded，让产品承担大量预估配置，也不能证明帧时间更好。

## 决策

采用[内存与容量策略](../memory-policy.md)：普通持久数据按需摊销/分块增长，帧内数据复用并在安全边界扩容，缓存按字节预算与引用状态回收。只对设备、格式、输入安全、背压和特殊实时路径保留有依据的限制。

取消“所有容器预先定死容量”“所有路径禁止动态分配”的全局约束。保留 owner-thread、generation、借用寿命、事务、取消和 GPU retirement 的正确性要求。

## 历史 ADR

部分修订 0011、0022、0023、0026、0028、0029 中的普遍固定容量要求，以及 0051 的单页硬容量作为最终架构的解读；不替代其布局、整形、交互组合、snapshot 和资源所有权决定。历史记录标注容量政策被本 ADR 部分替代，原有理由保留。

## 实施与验收

逐 owner 一次迁移实现、公开契约、消费者和故障测试；不留 alias/deprecated/兼容双轨。初始预留、软预算和硬限制分开。简单增大 reserve 数字不算迁移。

超过初始预留仍能正确增长，旧 handle/view 寿命可验证，长期占用不随历史操作总量增长；同 workload 对比分配、驻留和帧时间，无测量时不承诺性能倍数。
